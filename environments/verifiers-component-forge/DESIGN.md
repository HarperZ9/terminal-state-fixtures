# verifiers-component-forge: design spec

> Synthesized 2026-08-21 from a three-lens design fan-out with per-family
> adversarial critique (12 candidates, all kept, folded into 4 families).
> Target: Prime Intellect Application-Only bounty, verifiers library eval.

## Pitch

verifiers-component-forge is a single meta-environment where the agent writes or repairs verifiers components (Parser subclasses, Rubric wirings, MultiTurnEnv referees) against fully normative behavioral contracts, and scoring executes the emitted module through the real installed verifiers machinery in an oracle-free child process, comparing terminal state (extraction strings, metrics dicts, rewards, transcripts, stop reasons) against reference-derived frozen expectations. The reward path contains no judge model and never touches the network. It extends the mlflow-terminal-state methodology to the bounty's own subject library: exhaustively enumerated hidden probes, committed reference implementations, a load-time canary that re-derives every oracle constant against the installed verifiers so version drift fails loudly, and discrimination pinned by repo tests asserting the reference solution scores 1.0 while curated known-bad solutions score below stated ceilings. Four families share one harness and three thin child drivers, spanning a ladder from string-level parser contracts a mid-size open model can partially solve up to multiturn state machines that separate frontier models.

## Families

### parser-contract (parser-fallback-ladder with critique fixes applied)

**Task shape.** SingleTurnEnv. The prompt carries a precedence-ladder extraction contract in which every tie-break is normative: rung order, last-message-only scope, empty-tag-vs-missing-tag semantics ('' vs None), the both-tags-required think-strip rule, the definition of a non-empty line, the content-part join rule (join text parts with one space, then strip), and the full input domain (plain strings, dict messages, attribute-style message objects, list-typed content parts). Hidden inputs may be unseen instances, never unseen requirements. A pinned API digest and two worked examples appear in the prompt; worked examples are excluded from the scored set. The agent emits one module exporting build_parser() returning a vf.Parser subclass. The prompt states the completion-extraction rule verbatim: the last fenced python block wins.

**Terminal-state check.** Child driver P receives the module source plus hidden inputs as JSON on stdin, rebuilds dict and attribute-bag messages from recipes (never pickles), calls build_parser(), and runs parse_answer over each input under a per-input timeout and try/except, emitting result strings or null. The parent JSON-round-trips the results (coercing str subclasses to plain str, killing __eq__ exploits) and compares string/None equality against frozen expectations parent-side. Credit is weighted by grammar cell: the contradicting-rung, empty-vs-missing, think-strip, and multipart columns carry 45 percent of instance credit so a 15-line regex ladder plateaus visibly below a contract-faithful parser. A crash or hang costs only that input.

**Oracle.** One committed reference parser per ladder variant. The committed generator enumerates inputs from a deterministic grammar, runs the reference, and freezes expectations as constants. Repo tests assert that the installed XMLParser and ThinkParser diverge from the reference on the designated trap rows (cross-message fall-through on the chat path, empty string on missing close tag), so a library release that erases a trap fails CI instead of silently degrading discrimination. ASCII-only strings keep casefold and whitespace behavior stable across interpreters. Pure string transforms, so re-derivation is milliseconds on any machine.

**Dataset.** 96 instances over ladder permutations (depth 1-4, rung presence, scope, strip rules), roughly 24 hidden inputs each, about 2,300 probes. All inputs and frozen extractions committed as constants; regeneration is one command against the pinned verifiers.

### rubric-contract (rubric-arithmetic-contract with critique fixes applied)

**Task shape.** SingleTurnEnv. The prompt is a scoring contract: 2-6 named criteria with explicit weights including at least one zero and optionally one negative, aggregation stated as the raw weighted sum with no normalization, exclusion rules, and error semantics (malformed info yields criterion 0.0, never an exception). The prompt blesses a one-row stub dataset as the minimal valid environment, labels its 8-12 worked rows as rounded display values, and embeds the pinned Rubric call-protocol digest. The agent emits a module exporting load_environment() returning a vf.SingleTurnEnv whose Rubric implements the contract through the real reward-func machinery.

**Terminal-state check.** Child driver R builds the env and applies a structural gate before any case credit: type(env.rubric).score_rollout is vf.Rubric.score_rollout, reward-func __name__s exactly match the criterion names, and the weights vector equals the contract. It then constructs each hidden fixture state from JSON inputs and awaits score_rollout per fixture under try/except, emitting metrics and reward. The parent compares the exact metric key set, values, and reward at 1e-9 tolerance. Hidden tables are stratified so each targeted failure mode (weight normalization, malformed-info handling, exclusion rule, excluded-rollout-still-reports-diagnostic, negative weight, the group-func trap where the pinned version supports it) flips 15-20 percent of rows. Negative fixtures make a constant-1.0 rubric fail, and a repo test pins that floor.

**Oracle.** Committed reference rubric per contract, executed through the installed verifiers' real score_rollout at generation time; expectations frozen with a generation-time assertion that no value sits within 1e-9 of a rounding boundary (the grid parameter regenerates when one does). The load_environment() canary re-runs a case slice per contract against the installed verifiers and hard-fails with a version message on mismatch. Instances depending on version-specific internals (the completions-parameter group heuristic) are flagged so the canary disables them instead of letting them rot into noise.

**Dataset.** 96 instances crossing criterion count, weight-vector shape, exclusion and error variants, and trap on/off, with 12-20 hidden fixtures each, about 1,500 probes. Fixture inputs and frozen expectations committed as constants.

### rubric-repair (rubric-wiring-repair with critique fixes applied)

**Task shape.** SingleTurnEnv. The prompt renders one broken env module inline (under 300 lines, data hardcoded), a REWARD.md contract naming funcs, weights, and 0-weight metrics, one symptomatic vf-eval excerpt frozen as a constant at generation time, and 3 visible (completion, expected reward, expected metrics) pairs. The agent returns the complete repaired module in the last fenced python block. The README states the accepted-rewrite policy explicitly: terminal-state scoring grades behavior, not diffs, so a behaviorally equivalent rewrite passes by design.

**Terminal-state check.** The same child driver R scores this family: load_environment() on the repaired module, structural gate, then 12-20 hidden canned (completion, answer, info) fixtures replayed through the real Rubric.score_rollout, emitting reward plus all metric values including the 0-weight ones so stubbed diagnostics fail. The parent compares at 1e-9. Credit concentrates on the kill set (fixtures where broken and reference outputs disagree) with a smaller regression share over agreeing fixtures, so the verbatim broken module scores near zero and an over-eager rewrite that breaks untouched semantics loses regression credit. Every hidden battery carries per-func boundary fixtures (malformed tags, empty completion, tie cases) regardless of which mutation shipped, pushing battery equivalence toward semantic equivalence.

**Oracle.** 8 reference seed envs crossed with mutation operators grounded in real issue shapes, restricted to information-preserving builder-logic operators whose broken/correct contrast the load-time canary can assert under the installed verifiers. The kill-check ships a mutant only if it flips at least one hidden-split fixture and at least one visible pair; for every shipped mutant the reference is verified re-derivable from the mutant plus REWARD.md plus visible pairs alone. Reference envs and expectations live in the repo generator; the installed wheel carries only inputs and frozen constants, and the child never sees either. Repo tests pin the no-op submission below 0.2 and the reference repair at 1.0 on every shipped instance.

**Dataset.** 80 instances surviving the kill-check filter, drawn from roughly 260 raw mutants over 8 seeds and about 10 surviving operators; 3 visible plus 12-20 hidden fixtures per instance, about 1,200 probes.

### referee-protocol (multiturn-referee-protocol with critique fixes applied)

**Task shape.** SingleTurnEnv delivery (module as completion, no file tools, no rollout override anywhere). The prompt specifies a deterministic referee state machine: feedback alphabet with exact strings, memory rules like REPEAT, turn cap, invalid-input accounting, a reward schedule stated in exact tenths (integers over 10, so float phrasing cannot flake), and an explicit stop-reason winner when solve and cap fire on the same turn. The pinned MultiTurnEnv skeleton (env_response signature, the @vf.stop idiom, setup_state) is hardcoded in the prompt so the task measures composition against a stated contract rather than training-data recency. One or two worked scripts appear and are excluded from scoring. The agent emits a MultiTurnEnv subclass plus its Rubric.

**Terminal-state check.** Child driver M builds the env, asserts type(env).rollout is vf.MultiTurnEnv.rollout by identity (since @final has no runtime force), then replays hidden scripted conversations through the real pinned rollout() using a canned OpenAI-compatible client that raises a sentinel on script exhaustion. It emits normalized (role, content-string) transcripts, terminal rewards, turn metrics, and stop reasons. The parent compares transcripts as normalized pairs and floats at 1e-9, granting 0.5 partial credit for a matching transcript with a wrong terminal reward. Each script runs under asyncio.wait_for inside the child's own event loop (never nested in the vf-eval loop); a hang, an exhaustion sentinel, or an overridden rollout zeroes that script.

**Oracle.** The reference per instance is itself a MultiTurnEnv subclass run through the pinned rollout() with the same canned client at generation time, so frozen expectations capture the real loop's message interleaving and stop-condition ordering rather than an abstract model of it; a 60-line pure-function fold of the state machine cross-checks the reference in tests. Any spec row the reference cannot realize under the pinned version (cap-interaction ordering, stop-reason winner) is rewritten or dropped before shipping. The canary re-derives expectations per installed version.

**Dataset.** 64 instances crossing feedback alphabet, special rules, cap 3-9, and schedule shape, with 6-10 hidden scripts each pinning every branch: solve on turn 1, solve exactly at cap, all-invalid, repeat chains, unsolved timeout. About 500 script replays.

## Harness architecture

One meta-environment, one scoring shell, three thin child drivers. The outer env is vf.SingleTurnEnv with rollout never overridden; a Parser takes the last fenced python block from the completion. The single weighted reward func is async. It writes the module to a fresh temp dir, then launches a child via asyncio.create_subprocess_exec with sys.executable -I plus a parent-computed site-packages bootstrap (the critique confirmed -I -S cannot import verifiers, so -S is dropped and the parent injects resolved paths; a smoke test asserts verifiers imports under the exact production flags). The child gets a scrubbed environment with no API keys, cwd inside the temp dir, start_new_session=True with process-group kill on a 30-second wall clock, and POSIX rlimits (CPU, AS, NOFILE, NPROC) where the platform supports them, documented as best-effort elsewhere. The child receives inputs only: module source plus JSON case fixtures on stdin, with message objects rebuilt from recipes by the driver. Oracle values never enter the child's argv, environment, filesystem view, or importable modules; references and expectations live in the repo generator and the parent process, and a repo test greps every child-visible artifact for oracle values. The child installs an append-only sys.addaudithook that raises on opening or importing the meta-env package path, surfaced as a 0-weight tamper metric and documented honestly as a tripwire rather than a boundary. Three drivers share this shell: P runs parse_answer over inputs; R applies the rubric structural gate then replays fixtures through the real Rubric.score_rollout, serving both rubric families; M replays scripted conversations through the real MultiTurnEnv.rollout with a canned client. Each probe runs under its own try/except and timeout so one crash costs one probe, and one child per rollout amortizes the verifiers import. The child emits JSON on stdout after the loop completes; the parent parses it strictly as data, JSON-round-trips values to neutralize subclass and __eq__ exploits, and performs every comparison itself: strings exact, floats at 1e-9, transcripts as normalized pairs. Frozen constants ship in the package per Prime's hardcode rule, but load_environment() re-derives every expectation against the installed verifiers on first run, caches per version (Prime's heavy-preprocessing-cached escape hatch), hard-fails on unexplained mismatch, and disables flagged version-specific subsets cleanly. verifiers is pinned exactly in the env's pyproject, matched to the monorepo lockfile. load_environment(seed=None) defaults to the canonical frozen set so vf-install plus vf-eval needs zero config; passing a seed regenerates hidden grids through the committed generator for RL runs to blunt cross-epoch memorization. README documents the reward decomposition, the isolation threat model and why local hardened execution was chosen over a remote sandbox (the reward path must stay network-free), and the accepted-rewrite policy.

## Rubric

One weighted func: terminal_state_match (weight 1.0), the hidden-probe match fraction for the case computed parent-side with the documented per-family weighting: grammar-cell weights for parser-contract (edge cells carry 45 percent), stratified fixture tables for rubric-contract, kill-set concentration plus regression share for rubric-repair, per-script credit with 0.5 transcript-only partial for referee-protocol. Visible worked examples never enter the denominator. 0-weight informational funcs per Prime's convention: parsed_code_present, module_imports, structural_gate_pass, rollout_not_overridden, tamper_tripwire, crash_or_timeout, visible_examples_pass, and family_accuracy keyed by the row's task label. Discrimination is pinned by repo tests, not asserted: the committed reference solution scores 1.0 on every instance, and curated known-bad solutions (weight normalizer, dict-indexing of attribute-style messages, always-1.0 format reward, raising on malformed input, is_completed-era MultiTurnEnv, verbatim broken module) score below stated per-family ceilings. The PR includes vf-eval -n 5 -r 3 outputs on one weak and one strong model per family showing non-zero, non-saturated spread.

## Dataset total

336 cases: 96 parser-contract, 96 rubric-contract, 80 rubric-repair, 64 referee-protocol, carrying roughly 5,500 hidden probe comparisons. Every input and frozen expectation is committed as constants per Prime's hardcode rule and is re-derivable by one committed generator command against the pinned verifiers release. Nothing at generation or eval time touches the network or a model.

## Biggest risk

verifiers version churn. The whole targeted surface (Parser, XMLParser, Rubric.score_rollout, MultiTurnEnv, @vf.stop) now lives under verifiers/legacy behind alias shims while a v1 stack lands, so the frozen expectations, the trap-dependent discrimination story, and several repair mutation operators are all statements about one pinned release. The exact pin, the load-time re-derivation canary, and the behavior-pinning repo tests turn drift into loud failure instead of silent mis-scoring, but if Prime's monorepo resolution overrides the pin at review time, constants must be regenerated and flagged version-specific subsets disabled before producing the vf-eval evidence. De-risk on day one by generating constants against the exact verifiers version in the monorepo lockfile and keeping regeneration a tested one-command operation. The standing secondary threat, oracle leakage into the child, is handled architecturally (inputs-only child, parent-side comparison) and enforced by a test that scans every child-visible artifact for oracle values.

## First files

- environments/verifiers-component-forge/verifiers_component_forge/harness/runner.py - parent-side async subprocess shell: -I invocation with injected site-packages bootstrap, scrubbed env, process-group kill, JSON stdin/stdout protocol, all comparators; ships with the smoke test proving verifiers imports under the exact production flags
- environments/verifiers-component-forge/verifiers_component_forge/harness/child_driver_rubric.py - child driver R: structural gate (score_rollout identity, func names, weights) plus per-fixture score_rollout replay with try/except and timeouts; serves both rubric families and proves the real-library execution path end to end
- environments/verifiers-component-forge/generation/generate.py - offline generator and canary engine: runs committed references through the installed verifiers, freezes constants, enforces the rounding-boundary assertion and the hidden-split kill-check, and is reused verbatim by load_environment() for per-version re-derivation
